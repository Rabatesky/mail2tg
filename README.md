# mail2tg

Пересылает письма от выбранных отправителей из Gmail в Telegram.
Работает и с другими почтами по IMAP (Яндекс, Mail.ru) — достаточно поменять настройки в `.env`.

- Пересылает тему, отправителя, дату, текст (HTML-письма переводятся в обычный текст) и вложения.
- Длинные письма режутся на несколько сообщений, вложения приходят ответом на письмо.
- Письма в ящике **не помечаются прочитанными** и никак не изменяются.
- Помнит последнее обработанное письмо: после перезапуска ничего не теряется и не дублируется.

## Подготовка (5 минут)

1. **Пароль приложения Gmail.** Включите двухэтапную аутентификацию в аккаунте Google, затем откройте
   https://myaccount.google.com/apppasswords, введите любое название (например, `mail2tg`) и нажмите
   «Создать». Скопируйте 16-буквенный пароль — Google покажет его один раз.
2. **Бот в Telegram.** Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → сохраните токен.
   Откройте своего бота и нажмите «Старт».

## Установка на сервер (Debian/Ubuntu, root)

```bash
cd /root
git clone https://github.com/<ваш-аккаунт>/mail2tg.git
cd mail2tg
chmod +x install.sh
./install.sh                                  # зависимости, сервис, создаст .env
nano .env                                     # токен бота, Gmail, пароль приложения, FROM_FILTER
.venv/bin/python mail2tg.py --get-chat-id     # покажет chat_id → вписать в TELEGRAM_CHAT_ID
./install.sh                                  # проверит настройки, пришлёт тест и запустит сервис
```

По умолчанию (`BACKFILL_ON_FIRST_RUN=1`) сразу после запуска придёт последнее письмо от автора —
так видно, что всё работает. Дальше будут приходить только новые.

## Управление

```bash
systemctl status mail2tg              # состояние
journalctl -u mail2tg -f              # логи в реальном времени
systemctl restart mail2tg             # после изменения .env
.venv/bin/python mail2tg.py --check   # проверить почту и Telegram (пришлёт тестовое сообщение)
```

Обновление из гита: `git pull && ./install.sh`.

## Настройки (.env)

| Параметр | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_CHAT_ID` | куда слать; узнать — `--get-chat-id` |
| `TELEGRAM_PROXY` | прокси для Telegram, если `api.telegram.org` недоступен (`socks5://...`) |
| `IMAP_USER` | ваш адрес Gmail |
| `IMAP_PASSWORD` | пароль приложения (не обычный пароль!) |
| `IMAP_FOLDER` | папка, по умолчанию `INBOX` |
| `FROM_FILTER` | отправители через запятую, можно домен `@site.com`; пусто — все письма |
| `POLL_INTERVAL` | интервал проверки, сек |
| `SEND_ATTACHMENTS`, `MAX_ATTACHMENT_MB` | вложения и их лимит (у ботов не больше 50 МБ) |
| `MAX_BODY_CHARS` | обрезать очень длинные письма |
| `SHOW_LINKS` | показывать адреса ссылок из HTML-писем |
| `BACKFILL_ON_FIRST_RUN` | при первом запуске прислать N последних писем от автора |

Чтобы повторить первый запуск (например, снова получить последнее письмо), удалите `state.json`
и выполните `systemctl restart mail2tg`.

## Другие почты

| Почта | IMAP_HOST | Пароль |
|---|---|---|
| Яндекс | `imap.yandex.ru` | пароль приложения (id.yandex.ru → Безопасность) |
| Mail.ru | `imap.mail.ru` | пароль для внешнего приложения |

Порт `993`, `IMAP_SECURITY=ssl` — как у Gmail.

## Если что-то не работает

- **`AUTHENTICATIONFAILED` / `Invalid credentials`** — указан обычный пароль вместо пароля приложения,
  либо вы меняли пароль Google (пароли приложений при этом сбрасываются — создайте новый).
- **Нет страницы паролей приложений** — не включена двухэтапная аутентификация. У аккаунтов
  с «Дополнительной защитой» (Advanced Protection) и у некоторых рабочих аккаунтов Google Workspace
  пароли приложений недоступны.
- **Письмо автора не пришло** — проверьте, не попадает ли оно в «Спам» или не убирает ли его ваш фильтр
  из «Входящих»: скрипт смотрит только папку `IMAP_FOLDER`.
- **`Chat not found`** — вы не нажали «Старт» у бота или ошиблись в `TELEGRAM_CHAT_ID`.
- **Telegram недоступен с сервера** — задайте `TELEGRAM_PROXY`.
